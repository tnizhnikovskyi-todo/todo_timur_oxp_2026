# OXP 2026 — бюджет автопоїздки ToDo

Робочий документ поїздки команди ToDo на **Odoo Experience 2026** (Brussels Expo, 24–26.09.2026).

- **Джерело:** `src/document.html`
- **Сторінка:** https://todo-timur-oxp-2026.t-nizhnikovskyi.workers.dev
- **Опублікований артефакт:** https://claude.ai/code/artifact/619bc17d-817f-4ced-8164-cfa2ddc07f3e

## Структура

Документ поділений на сім вкладок:

| Вкладка | Що тримає |
|---|---|
| План дій | відкриті пункти, згруповані за тим, що від чого залежить |
| Пройдено | ухвалені рішення і перевірені факти |
| Учасники | склад, посади з Odoo, ролі на події |
| Маршрут | графік дев'яти днів, маршрут, пробіг, дві машини |
| Бюджет | перепустки з ПДВ, постатейно, зведення |
| Витрати | план проти факту, журнал платежів |
| Документи і бронювання | місце для підтверджень броні, полісів, договорів |

Закритий пункт переїжджає з «Плану дій» у «Пройдено»; якщо він коштував грошей —
той самий факт іде у «Витрати».

## Домовленості по вмісту

**Кожна адреса — клікабельна.** Будь-яка адреса в документі загортається в
посилання на карту класом `.addr`:

```html
<a class="addr" href="https://www.google.com/maps/search/?api=1&query=<адреса>"
   target="_blank" rel="noreferrer">Kerkstraat 23</a>
```

Для точок, на які вже є конкретне посилання з чату (наприклад АЗК KLO у
Стоянці), береться саме воно, а не пошук за текстом. Підкреслення пунктиром
показує, що адреса відкривається на карті. Сенс простий: у дорозі відкрити
карту має бути одним дотиком, а не копіюванням тексту.

**Усе з групи, що не сміття, потрапляє у файл.** Група OXP 2026 у Telegram —
джерело, документ — підсумок. Кожне повідомлення з групи або відображається в
документі, або свідомо відкинуте як балачка. Розкладається за змістом:

| Що прийшло | Куди йде |
|---|---|
| платіж, сума, рахунок | «Витрати» — журнал і зведення, плюс перерахунок у «Бюджеті» |
| ухвалене рішення | «Пройдено», а відповідний пункт зникає з «Плану дій» |
| нове питання без відповіді | «План дій», у групу за строком |
| адреса, час, точка | «Маршрут» — і адреса одразу посиланням на карту |
| факт про подію | «Подія» |
| документ, бронь, поліс | «Документи і бронювання» |

Сміттям вважається те, що не змінює жодного рядка документа: вітання, реакції,
дублі, повідомлення про підключення бота. Якщо повідомлення суперечить наявним
цифрам — воно все одно вноситься, але з позначкою «з групи, не підтверджено»,
і розрахунок не переписується мовчки.

**Пройдене прибирається з плану.** Те, що фактично сталося, переїжджає в
«Пройдено» з датою і рядком про результат, а відповідний пункт зникає з «Плану
дій». Межа тут одна і вона жорстка: **прострочений пункт — не виконаний
пункт**. Строк минув, а питання відкрите — пункт лишається в плані, строк
пересувається на реальну дату.

Дні, які минули, документ гасить сам: у графіку поїздки рядок за вчорашнє
число тьмяніє і отримує ✓, сьогоднішній підсвічується, а програма події
відкривається на поточному дні. Це рахує браузер за своєю датою, не автор і не
розклад — тому воно не може помилитися і його не треба правити руками.

**Назви доповідей живуть у двох мовах.** Переклад лежить окремим блоком
`<script id="oxpProgUa">` поряд із `oxpSessions` і зіставляється з ним **за
порядком**: `t[i]` — назва сесії `DATA[i]`, `g` — теми, `r` — посади спікерів.
Якщо довжини розійдуться, скрипт мовчки лишає англійські назви, а не показує
чужі. Тому дані програми не перетасовуються: доданий рядок у `oxpSessions`
вимагає рядка в `t` на тій самій позиції (порожній рядок = перекладу немає,
показується оригінал).

Англійський оригінал видно завжди — у розгорнутій сесії, незалежно від
перемикача. Це не надмірність: на бейджах, табло залів і в застосунку Odoo
написано саме його, тож шукати зал по українській назві не вийде. Пошук
працює по обох мовах одночасно. Назви залів (`Auditorium 4000`, `Hall 7.B`)
не перекладаються взагалі — це напис на дверях.

Обидві роботи — розбір групи і чистка пройденого — ідуть щогодини самі
(Routine `trig_01K4cc4nzwavEri5c6S8wJ7B`), плюс на вимогу: «глянь групу».

## Чому потрібна збірка

`src/document.html` написаний як **тіло** сторінки, без `<!doctype>`, `<html>` і `<head>` —
так його вимагає обгортка артефакта claude.ai, яка ці теги додає сама. Для звичайного
хостингу вони потрібні свої: без doctype браузер іде в quirks mode, а без
`<meta charset>` кодування залежить від заголовків сервера.

`build.sh` бере тіло, обгортає його в `wrapper/head.html` і `wrapper/tail.html`,
прибирає з тіла дубльований `<title>` і складає все в `dist/`:

```bash
bash build.sh      # → dist/index.html, dist/robots.txt, dist/_headers
```

`dist/` не комітиться — це результат збірки.

## Хостинг на Cloudflare Workers

Cloudflare веде нові проєкти через Workers, а не Pages, тому деплой іде командою
`npx wrangler deploy`, а конфігурація лежить у `wrangler.toml`. Секція `[assets]`
без ключа `main` означає воркер без коду: віддавай файли з `dist/` як є.

**Налаштування проєкту** (Compute → Workers & Pages → Create → імпорт репозиторію):

| Поле | Значення |
|---|---|
| Репозиторій | `tnizhnikovskyi-todo/todo_timur_oxp_2026` |
| Project name | `todo-timur-oxp-2026` — має збігатися з `name` у `wrangler.toml` |
| Build command | `bash build.sh` |
| Deploy command | `npx wrangler deploy` |

Після цього кожен пуш у гілку сам перевидає сторінку.

Локально конфіг можна перевірити без доступу до Cloudflare:

```bash
bash build.sh && npx wrangler deploy --dry-run
```

### Доступ

Сторінка **публічна**: хто має посилання, той її бачить. Це свідоме рішення —
контроль доступу не налаштовуємо, просто не роздаємо посилання зайвий раз.

Щоб це рішення справді працювало, індексація заборонена на трьох рівнях:

- `wrapper/head.html` — `<meta name="robots" content="noindex, nofollow, …">`;
- `static/robots.txt` — `Disallow: /` для всіх роботів;
- `static/_headers` — заголовок `X-Robots-Tag`, який діє навіть тоді, коли на
  сторінку хтось поставить посилання зі свого сайту.

`_headers` у Workers підтримується: wrangler читає його з каталогу активів
окремо і передає платформі як правило, а не як публічний файл. Перевірити
після деплою:

```bash
curl -sI https://<адреса> | grep -i x-robots-tag
```

Якщо колись знадобиться закрити доступ по-справжньому: у формі створення проєкту
є перемикач **Protect with Cloudflare Access**, його можна включити й потім —
безкоштовно до 50 користувачів, політика на кшталт «пошта закінчується на
`@todo.ltd`» з одноразовим кодом на пошту.
